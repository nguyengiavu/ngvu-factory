Before anything is built

Intake gates

Investigation first

tasks\VUNG-<n>-<slug>\ must exist (ngvu-ticket-investigation; an Epic needs ngvu-epic-investigation). From a log or Sentry signal: ngvu-triage drafts the ticket. Repos come from 04-IMPLEMENTATION-PLAN.md, resolved by repo-path.sh with their kind; a 04 still holding the template AC-1 WHEN ... counts as not investigated and stops the intake.

Open-question gate

An unanswered question that can change an AC, authorization, a contract, stored data or failure behaviour blocks spec and build. Answer it, or reply build on defaults Q12, Q14 - the approver still escalates each.

Branches

Names only from branch-name.sh; existing branches with the key are listed and never reused.

Claims

An epic child is claimed atomically; a declined intake releases the claim; close keeps it.

Approval gate

Escalation

APPROVE means "push the branch and hand over the PR link". These always go to a human:

Flyway migration, Mongo index, backfill, data shape
Authorization, MP JWT, tenant isolation
Contract used by another repo
CI, Dockerfile, deployment, standalone.xml, new dependency
Failure behaviour not in the AC
User-facing strings (translation files, every supported locale)
Unanswered or accepted-default open question
Related IT without IT: PASS from you
A repo owned by another team is not a trigger: it is listed under "Other-team repos" so that team gets the PR for information.

Epic flow

epic vung-<e>Factory queue (breakdown.sh) + Jira children, Blocks links
→
You approvethe queue
→
EPIC branchcreated and pushed
→
next vung-<e>per session
→
Ticket loopslide 6
→
PR mergedinto the epic branch
→
finish-epicDoD check, epic PR links
  • The queue is the keyed stories of 08-STORY-BREAKDOWN.md § Factory queue, checked by breakdown.sh; Test and Sub-task children are never queued.
  • A blocker is done only when its own work is merged into origin/<epic branch>; a closed blocker is shown to you to decide. A blocker merged straight to master (exit 23) stops the child's intake: you choose a reviewed PR bringing master into the epic branch, or building the child with --independent from origin/master.
  • Children without an investigation (no folder, or a template 04) are never started; next refreshes them first and skips children already Done in Jira.
  • finish-epic lists never-built children for you to decide, re-runs breakdown.sh and checks the epic DoD before the PR links.
  • Sessions in the same repo share .git and ~/.m2: run different repos in parallel. Cost: about seven agents per round.
13 / 16
Mechanism, not only a prompt

Guardrails

ngvu_guardrails.py Bash, PowerShell

Parses the command. Allows only git [-C <repo>] push [-u] origin <vung-n branch>. Blocks refspecs, force, master/develop/release, push aliases, destructive git, acli Jira writes.

guard.sh Bash, PowerShell, Edit, Write

Blocks kubectl/helm/terraform/gcloud changes, Vault, destructive Mongo, rm -rf, release scripts. Asks before edits to compose, .env, credentials, example_deploy, Claude settings.
Both fail closed (onFailure: block): no working python or bash means every shell call is blocked - run doctor. Atlassian MCP write tools are denied in settings.json; a Bash(git push:*) deny alone would miss git -C <repo> push.
